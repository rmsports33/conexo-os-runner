Scheduled Tasks and the four local scripts they depend on. The repository does
not contain task exports, launchers, credentials, logs, queue files, reports,
database files, or any other machine-local state.

## Relationship with existing versioned modules

The four workers are not duplicates of the three existing tracked PowerShell
entry points (`run-once.ps1`, `install-task.ps1`, `uninstall-task.ps1`):

* `run-once.ps1` drives the versioned SQLite queue, safe recovery, backup,
  module inventory and status generation.
* AutoOps diagnoses the private core and orchestrates preview/status helpers.
* QueueWorker uses a separate legacy JSON operations queue and a bounded
  recovery policy; it only reads Scheduled Task status for allowlisted names.
* TaskExecutor is an explicit JSON dry-run inspection path.
* Watchdog emits a two-task health report.

The Python modules under `scripts/` cover SQLite queue ownership, recovery,
worker execution, maintenance and portable status. They do not replace these
legacy JSON/status paths. Consolidation is a later architectural decision; this
change only prevents loss of the code currently used in production.

## Security boundaries

* No passwords, tokens, private keys, `.env` files, task XML, or state files
  are versioned.
* `conexo-task-executor.ps1` remains `DRY_RUN` and does not start a task.
* `conexo-autoops-check.ps1` invokes synchronization only in preview mode; it
  never supplies `-Publish`.
* Runtime writes are limited to the ignored `local-state` directory or to the
  explicitly guarded local portable-status destination in the private core.
* The hosted Windows CI parses every script without executing it.

```powershell
# Syntax only — does not execute a worker.
$files = @(
  'windows/conexo-autoops-check.ps1',
  'windows/conexo-queue-worker.ps1',

)
foreach ($file in $files) {
  $tokens = $null
  $errors = $null
  [System.Management.Automation.Language.Parser]::ParseFile(
    (Resolve-Path $file), [ref]$tokens, [ref]$errors
  ) | Out-Null
  if ($errors.Count) { throw "$file has parse errors: $errors" }
}
```

## Recovery procedure

1. Obtain the reviewed commit or release that contains these eight files.
2. Verify repository and file hashes before copying anything.
3. Stop and export the affected Scheduled Task **only in a separately
   authorized maintenance window**. This pull request does not do that.
4. Restore the reviewed files to the repository `windows` directory.
5. Parse all scripts using the syntax-only command above.
6. Confirm launcher targets and task XML by inspection before re-enabling or
   running any task.
7. Keep queue, report, log, database, and task XML files outside Git.

Rollback is a normal Git revert of the preservation commit. A private local
backup of the pre-preservation files and task XML must be retained until the
reviewed commit is integrated and validated in a maintenance window.
